Command Entry Panel Overview

Command Input

  • Enter a CL command or SQL statement into the input area and press Enter or Run to execute it.
  • Press F4 or select Prompt to invoke the CL prompter (CL commands only).
  • You can also invoke prompting by placing ? before the command name.
  • Use F9 and F8 to retrieve prior CL or SQL statements from the history log.
  • The Up and Down Arrow keys may be used instead of F9 and F8, respectively.

Command Entry Panel Highlights

Command Entry Control Menu

  • Show/Hide Message Details
    Toggle the detailed message information for each CL command in the local joblog. This is similar to the F10=Detailed messages option on the IBM i Command Entry screen.
  • View CL History
    Open the history panel to review previously run CL commands and any logged SQL statements. By default this history is shared across all IBM i connections, but it can be scoped to the active connection in Command Entry settings.
  • Clear CL Cmd History
    Clears the CL Command History immediately. All history is removed from the history log for this connection or everything if History is not scoped to the Connection.
  • Clear SQL Stmt History
    Clears the SQL Statement History immediately. Only SQL statement history is removed from the history log for this connection or everything if History is not scoped to the Connection.
  • Clear All Log Entries
    Clears the CL commands and their associated messages from the Command Entry joblog (the log that appears below Command Entry input area). input.
  • Clear SQL Log Entries
    Clears all SQL statements and their associated messages from the Command Entry joblog (the log that appears below Command Entry input area).
  • Log SQL Statements
    Toggles whether or not SQL statements run on Command Entry are recorded in the Command entry joblog. Note that when an error occurs on an SQL statement it is logged regardless of this setting in order to report that error.
  • Run Mode
    This setting allows to you run or only syntax check CL commands. The valid choices include:
    • Run - Run commands normally
    • Limit - Run commands as a *LIMITTED user profile.
    • Check - Syntax checking-only.
  • Connection Settings...
    Opens the Settings panel that controls the active IBM i SQL Job connection settings. This includes the type of job (shared or private). If a Private SQL Job is selected, then additional options are provided, including: startup settings, a Script to run after connection is established, SET PATH/SCHEMA, and a pivot option.
  • Reconnect Server Job
    Used when a private/dedicated SQL Job is used by Command Entry. It will force a mini-end/restart of the SQL Job. We call this "reconnect". It will attempt to reconnect to the same SQL Job and its attribute will be as if it were a new job. If it cannot reconnect, then a new SQL Job is created and attached.
  • Cancel Last SQL Statement
    If you run an SQL statement from Command Entry and that SQL statement is running too long and you want to cancel it, this option can be used to attempt that cancellation. It is not guarantted to cancel it but it will attempt to do so. Technically this option could also work with a long running CL command but in practice I have never seen it successfully cancel a CL command.

Command/Statement History Log

  • Each CL command, and optionally each SQL statement that is run, is recorded in the history log.
  • By default, the history is shared across all IBM i connections.
  • If you enable the connection-scoped history setting in Command Entry settings, each connection keeps its own separate history.
  • From the Command Entry input area, you may use the retrieve functions (F8/F9 or arrow Up/Down) to retrieve prior CL commands or SQL statements.
  • You can control whether SQL statements are recorded in the history log in Settings.
  • The History Log can be cleared of all prior CL commands, all prior SQL statements, or both.

Results and Message Log (Joblog)

  • Each command execution is added to the log that appears below the input area. Each entry has a timestamp and elapsed time.
  • Messages from that execution are listed below the command or SQL statement.
  • Messages may be collapsed or expanded using F10 or the "Collapse" menu option.
  • Individual commands and their messages may also be collapsed or expanded to reveal second-level message text and from/to program information.
  • The SEV selector can be used to filter out messages below the specified severity.
  • You can control whether SQL statements in addition to CL commands are logged, via settings.

SQL Results Window

  • SQL statements open in a dedicated results tab/view.
  • Each column in the result set may be sorted or resized.
  • Page controls provide simple navigation to the next/prior page and the top/bottom of the result set.
  • An <SQL> button can be used to reveal the full SQL statement that produced the results.
  • A Refresh button allows the statement to be run again.
  • Column heading hover text provides more details about column/field attributes.

Code Snippets

Code snippets provide a fast way to run pre-written SQL statements. Initially, we include several snippets that mirror tasks such as Work Active Jobs, SPOOLED Files lists, and Display Library List.

  • Code Snippets provide reusable SQL statements for common tasks.
  • Built-in snippets are grouped by category and can be run directly.
  • In future releases, user-written code snippets can be created, edited, reordered, imported, and exported.
  • To run a Code Snippet, click on the snippet in the tree view sidebar, then press the Run button.
  • A custom setting allows you to set the action that occurs when you click on the snippet. For example, you can set the action to NOOP (the default) so nothing happens, or you can set it to "Run" to automatically run that code snippet when it is clicked.

SQL Job Controls

Command Entry can use its own SQL job or share the same job as the Code for IBM i extension. The preference is to use its own dedicated job.

This dedicated job support is available only when Mapepire is used in server mode. Although we can internally create a distinct job when Mapepire is not used in server mode, JVM startup time makes that configuration impractical, so we have disabled it in the so-called "single-user" mode.

  • The Command Entry status line contains the active SQL job being used by Command Entry.
  • To view the joblog for the SQL job, simply double-click on the job ID in that status line.
  • Use your Connection Settings and CL Prompter settings to control which mode (shared or dedicated job) to use.
  • A "Reconnect Server Job" menu option allows you to reconnect to the IBM i host, similar to how ACS RUNSQL Scripts Reconnect performs. This applies only to the dedicated SQL job and does not work when the Code for IBM i SQL job is being shared.
